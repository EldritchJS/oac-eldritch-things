# ServiceMonitors the Prometheus Operator rejects, accepted as recorded gaps
# for verify.sh T-27. One per line: <namespace>/<name> <reason>. A rejected
# ServiceMonitor not listed here FAILs.
#
# A rejected ServiceMonitor collects nothing and says so only in an
# InvalidConfiguration event, so the namespace looks monitored while no data
# arrives. Only the absence of metrics gives it away, which is why this
# check exists.
#
# All of these have the same cause: the operator writes a ServiceMonitor for
# platform monitoring (bearer token file, platform certificate paths) into a
# namespace carrying no openshift.io/cluster-monitoring label, so the
# platform Prometheus will not read it and user workload monitoring refuses
# anything that reads the filesystem. We own every one of these namespaces
# through a chart, so all six are fixed by oac-apps#302, which gives
# operator-library.namespace the ability to carry labels and sets this one.
# Remove these lines when that merges. MOC-issues #834.

metallb-system/controller-monitor fixed by oac-apps#302. No MetalLB metrics on any cluster, production included, until it merges
metallb-system/speaker-monitor fixed by oac-apps#302. The speaker metrics are how L2 or BGP trouble would show
external-dns-operator/external-dns-operator-metrics-monitor fixed by oac-apps#302
openshift-storage/lvms-operator-metrics-monitor fixed by oac-apps#302. Also unblocks prometheus-lvmo-rules, whose topolvm_* metrics exist nowhere today because this monitor is rejected
openshift-nfd/nfd-controller-manager-metrics-monitor fixed by oac-apps#302. Hypervisor rather than hub; same shape as openshift-storage, with its own alert rule waiting on the same metrics
patch-operator/patch-operator-controller-manager-metrics-monitor fixed by oac-apps#302, though moot in the medium term: patch-operator is being removed (MOC-issues #831)
